## 0. The framing this plan corrects

The obvious reading of 8.1 is "six roles came back NOT SHOWN, so six agents need
fixing". The evidence does not support that, and acting on it would send the work
to the wrong place.

**NOT SHOWN is a statement about the evidence, not about the agent.** It means
the cheaper arm's non-inferiority was not established. For three of the six, the
arm that actually ships scores 96–100% and nothing about the shipped
configuration is in question — what is unproven is a *cost saving nobody has
taken*.

Accuracy of the arm that ships, from `docs/evidence/matrix-81.json`:

| role | ships | shipped-arm accuracy | below the 95% floor? |
|---|---|---|---|
| `evor-forge-analyst` | opus | 100.0% (60/60) | no |
| `evor-acquirer` | haiku | 98.3% (59/60) | no |
| `evor-probe` | haiku | 98.2% (54/55) | no |
| `evor-forge-architect` | opus | 98.0% (49/50) | no |
| `evor-forge-critic` | opus | 98.0% (49/50) | no |

So the quality question is about **three** roles, not nine.

## 1. And two of those three are spec defects, not agent defects

Reading the actual failures before prescribing a fix — the discipline item 8.x
was built on — two of the three dissolve.

### `evor-sage-junior` — the fixture cites a real paper for a claim it does not make

`divergence-just-inside-comparable` scores **0/5 on both arms**. The model
returns `findings: []` and explains why: the case attributes *"94.2% on the
standard IAM test split"* to `arxiv.org/abs/1507.05717`, which is Shi et al.'s
CRNN **scene-text** paper — benchmarked on IIIT5K, SVT and ICDAR, not IAM
handwriting. The second source is a CVF URL whose slug does not follow the
site's pattern.

`agents/evor-sage-junior.md` says a citation whose provenance cannot be
established *"does not exist"* for reporting purposes, and *"if you cannot cite,
you cannot assert."* The model followed that rule exactly and refused to
manufacture a quorum from a mismatched source. **The spec scores that refusal as
a failure**, which makes the case a test of whether the agent will cite a paper
that does not support the claim.

### `evor-tick` — the case demands a pointer it makes impossible

`failed-tick-carries-its-reason` supplies a `failure` object and **no artifact,
no signal and no `run_id`** — while `expect.pointers.min` is 1. A pointer is a
`run_id`/`tick`/`agent` triple, so the payload cannot produce one.

`agents/evor-tick.md:100` does require *"a pointer to whatever artifact or signal
explains it"*, so the rule is grounded — but this case supplies neither. The runs
that scored **correct did so by inventing a pointer**; the run that returned `[]`
was marked wrong. The case as written rewards fabrication.

### `evor-sage` — genuine, and the only one of the three that is

Three cases fail on `confidence` and `quorum_met` around the comparability gate.
These are real judgement disagreements on subtle rules, not fixture errors. This
is the one row where "the agent or its instructions may need work" is the honest
reading, and it is also the row that ships on haiku below the floor.

## 3. The permission affordance (item 2.8)

75 of 930 calls (8.1%) contain the model reporting that a tool it was *instructed*
to call was denied by the permission system. Only **1** scored incorrect, so 8.1's
results stand — but this is the release's own subject appearing inside the
measuring instrument: the harness attaches the MCP server, the agent is ordered to
call it, and the call is refused. The agent then narrates the refusal, which is
where 8.2's prose-before-JSON prefixes come from.
