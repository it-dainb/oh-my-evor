# v1.2.1 — test deletions and weakenings ledger

Release criteria §5.3 and §5.4. A row is required for every test **removed** and
every assertion **weakened** in `tests/test_wave1_*.py` or `tests/wave1-*.test.ts`
— and, by the same logic, anywhere else a phase changes what a test pins.

A count-only ledger is satisfied by neutering a test in place, which is precisely
what `integrity.py:404`'s `return True` already is. So the trigger is not deletion.

**Classification is mechanical, not editorial.** A row may be filed *modified*
only if its diff touches no assertion line:

```
git diff <phase-base> -- <file> \
  | grep -E '^[-+].*(expect\(|assert|toBe|toThrow|pytest\.raises)'
```

Empty → legitimately *modified*. Non-empty → it is a *weakened* or *corrected*
row and carries the fuller justification below.

## Phase 1 / 3 — a removed guard

`hooks/stop.mjs` drift-guard **check (c)** is removed, deliberately, under §1.2 and
Risk 4 ("where a phase deletes a call site, delete its test deliberately and record
why"). It pushed `tick N appears mid-flight` when `current_step < 9` and the run was
live — the same condition Guard 3's continuation check owns, evaluated one guard
earlier, with a message that named the problem but not the remedy.

No coverage is lost: the condition still blocks (exit 2), now via the guard that
tells the agent to call `TaskOutput` with `block:true` or `Monitor` the artifact it
owes. `mcp/tests/stop-incomplete-tick.test.ts` covers it end to end and is green.

`hooks/stop.mjs`'s drift guard is also now **scoped to the orchestrator**. It never
was, and only looked scoped because its gates were inert; a sub-agent ending its own
turn was being asked to produce the artifacts it had been spawned to produce.
`stop-incomplete-tick.test.ts`'s "the guard is scoped to the orchestrator" cases had
asserted this all along and were passing for the wrong reason.
